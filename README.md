# UpgradeLens — Upgrade Impact Verifier for Dependency Pull Requests

> **Answers:** *“If I upgrade this dependency, which parts of my application could break, and what evidence supports that conclusion?”*

**Project Owner:** G. Anil Kumar  
**Destination Repository:** [https://github.com/anilkumargadi27-hub/Upgrade-Impact-Verifier.git](https://github.com/anilkumargadi27-hub/Upgrade-Impact-Verifier.git)  
**Branch:** `main`

---

## 1. Overview & Core Contract

UpgradeLens is a developer-tool platform that verifies dependency upgrades by pairing **TypeScript AST static analysis** with **isolated, comparable check executions** (build, type-check, automated tests).

### Four Pillars of Credible Evidence
Every report generated by UpgradeLens separates:
1. **What changed in the dependency** — AST exported declaration diffs and release notes.
2. **Where the application uses the affected API** — TypeScript AST scanner pinpointing exact files, line numbers, and bounded code snippets.
3. **What the checks actually observed** — Pairwise comparison of identical commands in baseline and upgrade workspaces.
4. **What remains uncertain** — Explicitly documented boundary conditions and limitations.

### Four Verification Verdicts
| Verdict | Meaning |
| :--- | :--- |
| `REGRESSION_OBSERVED` | Comparable checks pass on baseline and fail after upgrade. |
| `POTENTIAL_IMPACT` | Source/API evidence indicates possible incompatibility, but check executions do not establish a regression. |
| `NO_REGRESSION_OBSERVED` | Executed comparable checks show no regression (or removed exports are proven unused). |
| `INCONCLUSIVE` | Baseline failures, missing checks, execution timeouts, or infrastructure errors prevent a reliable conclusion. |

## 2. Supported Scope & Boundaries

UpgradeLens provides strict input validation:
- **Supported:** Public GitHub repositories (JS/TS), single root-level package, npm with valid `package-lock.json`, 1 direct dependency upgrade per analysis, standard npm registry packages.
- **Explicitly Rejected:** Private repositories, monorepos/workspaces (pnpm, yarn, bun), missing lockfiles, PRs with multiple dependency changes or manual source modifications.

## 3. Architecture

UpgradeLens is implemented as a TypeScript monorepo:
```
.
├── apps
│   ├── api          # Express REST API, SSE streaming, Auth, OpenAPI (/api)
│   ├── web          # React + Vite + Tailwind dashboard & report explorer
│   └── worker       # Orchestrator, GitHub ingestion, Gemini AI adapter
├── packages
│   ├── contracts    # Shared Zod schemas, DTOs, and event contracts
│   ├── analyzer     # TypeScript AST scanner & declaration diff engine
│   └── runner       # Isolated process-tree bounded runner with timeouts
├── fixtures         # 8 ground-truth test scenarios & mock packages
├── docs             # Architecture, Security, Decisions, Demo guides
├── infra            # Dockerfiles & production compose setup
└── docker-compose.yml
```

### Dual-Mode Database & Queue Architecture
- **Zero-Prerequisite Local Mode:** Uses Prisma 6 with `@electric-sql/pglite` and an in-process queue adapter. Starts instantly on any machine without Docker, PostgreSQL, or Redis daemon installation!
- **Production Mode:** Native PostgreSQL connection and BullMQ over Redis on Render or Docker.

## 4. Quickstart

### Prerequisites
- Node.js >= 20.0.0
- npm >= 10.0.0
- Git

### Installation
```bash
# Clone repository
git clone https://github.com/anilkumargadi27-hub/Upgrade-Impact-Verifier.git
cd Upgrade-Impact-Verifier

# Install monorepo dependencies
npm install

# Generate Prisma Client
npm --workspace=@upgradelens/api run db:generate

# Build all packages and applications
npm run build
```

### Running Locally
```bash
# Start API & Unified Web Server
npm start
# -> Access UpgradeLens at http://localhost:4000
```

Or run all services in developer live-reload mode:
```bash
npm run dev
# -> Web UI at http://localhost:3000 (proxies API to :4000)
# -> API server at http://localhost:4000
# -> Worker listening for jobs
```

## 5. Automated Verification & Testing

### Run Vitest Suite (Unit & Integration Tests)
```bash
npm test
```

### Evaluate Ground-Truth Fixture Suite (8 Scenarios)
The fixture suite runs all 8 scenarios through the real end-to-end pipeline:
```bash
npm run evaluate:fixtures
```
Scenarios verified:
1. `scenario-1`: Removed export used by application -> `REGRESSION_OBSERVED`
2. `scenario-2`: Changed required argument detected by type checking -> `REGRESSION_OBSERVED`
3. `scenario-3`: Compatible update -> `NO_REGRESSION_OBSERVED`
4. `scenario-4`: Baseline already failing -> `INCONCLUSIVE`
5. `scenario-5`: Missing tests -> `NO_REGRESSION_OBSERVED` (with limitation notice)
6. `scenario-6`: Execution timeout -> `INCONCLUSIVE`
7. `scenario-7`: User cancellation -> `CANCELLED`
8. `scenario-8`: Removed export that application never uses -> `NO_REGRESSION_OBSERVED` (proves usage awareness)

## 7. Security & Privacy

- **Argon2id** password hashing.
- **HttpOnly**, `SameSite=Lax` session cookies with SHA-256 stored token hashes.
- **Strict Execution Isolation:** Subprocesses are launched with isolated temporary workspaces, timeouts, and process-tree termination (`taskkill` on Windows, process groups on Linux).
- **Secret Isolation:** Environment secrets are never passed into analyzed application workspaces.
- **Ownership Verification:** All project, analysis, SSE, and artifact routes strictly verify authenticated user ownership.
